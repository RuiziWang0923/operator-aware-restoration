# Operator-aware restoration

Scientific companion to *From correction capacity to correction control: operator-aware evaluation of image restoration*, manuscript v4.1.2. The repository provides PAST, JOME, and ARISE model implementations and evaluation weights, native-resolution benchmark inference, the 800-image evidence records and analysis code, and editable manuscript sources with tables and figures.

Repository: [operator-aware-restoration](https://github.com/RuiziWang0923/operator-aware-restoration). Code author: Ruizi Wang ([ORCID 0000-0002-6646-9907](https://orcid.org/0000-0002-6646-9907)); contact: [454762251@qq.com](mailto:454762251@qq.com).

## Reproduce the numerical evidence

Use Python 3.11 or later:

```bash
python -m pip install -r requirements.txt
python scripts/reproduce.py
```

The command validates all 800 image records and their split membership, fits mixtures only on the 300 selection images, and writes eight numerical table CSVs, five quantitative plot PDFs, and `results.json` under ignored `outputs/`. All 208 displayed numeric table values, including Table 3 interval endpoints, are checked against the supplied manuscript at stated rounding precision. The framework table is conceptual; it has no numerical replay.

The replay covers historical fixed-backbone summaries, matched aggregation, MSE/mean-PSNR calibration, the capacity context, two-baseline outcomes, reachability, and near-identity geometry. Quantitative plots reproduce the evidence underlying Figures 1, 2, 3, 5, and 6 with new plotting layouts. Supplied manuscript PDFs remain the publication artwork. Figure 4 contains four purposefully selected native image exports and is supplied as publication artwork. Its IDs, raw/released scores, display protocol, checkpoint identities, and source-image hashes are recorded in `data/qualitative_examples.json`; it is not regenerated by the statistical replay.

`scripts/analyze_priority.py` provides the E1–E3 record validation, MSE fitting and original matched-operator intervals. The mean-PSNR replay uses the manuscript's barycentre, vertices and 32 deterministic interior starts with SLSQP and analytic gradients. The original initialization seed and start distribution are unavailable; replayed coefficients match at displayed precision. This nonconvex fit has no global optimality guarantee.

All intervals use 5,000 paired image resamples with fixed weights. The original priority-analysis official E1 interval has upper endpoint 0.015774 dB, versus 0.0150 in the manuscript table. Implementing the manuscript’s documented common-resampling protocol, with random state `20261013 + role_index` (selection 0, official 1, internal holdout 2), recovers all displayed Table 3 endpoints and the textual calibrated F4P endpoints. The original manuscript bootstrap implementation is unavailable. `results.json` also retains the original priority-analysis intervals. Intervals omit model-seed/calibration uncertainty; splits are retrospective and scene identifiers are unavailable.

Tested locally with Python 3.14, NumPy 2.4.4, SciPy 1.17.1, and Matplotlib 3.10.9. See [DATA.md](DATA.md) for field definitions and evidence-to-manuscript mapping.

## Evaluate PAST, JOME and ARISE

The evaluation weights implement the three named systems in the paper. JOME and ARISE each combine an add-on with the same frozen PAST backbone, provided once as `base.pt`.

| System | Evaluation weights | Epoch | Required backbone |
|---|---|---:|---|
| PAST | `checkpoints/base.pt` | 159 | Self-contained |
| JOME | `checkpoints/jome.pt` | 80 | `checkpoints/base.pt` |
| ARISE | `checkpoints/arise.pt` | 80 | `checkpoints/base.pt` |

[MODEL_MANIFEST.json](model/MODEL_MANIFEST.json) records model configurations, parameter counts, validation-selected epochs, source run identities and SHA-256 hashes. The three EMA checkpoints occupy about 107 MiB and are byte-identical to the weights used for the recorded evaluations.

Obtain the image/reference pairs from the [OpenRR-5k provider](https://huggingface.co/datasets/qiuzhangTiTi/OpenRR-5k). For the official split, use `val_300_blended.zip` and `val_300_transmission.zip`, placing their image files under `data/val/input/` and `data/val/target/` respectively (for example, `data/val/input/val_0001.jpg`). Preserve the original filenames and encoded bytes; some `.jpg` targets contain PNG data, which Pillow reads correctly. Selection/internal-holdout evaluation additionally uses training pairs listed in `data/manifest.csv`. Then run directly from this repository:

```bash
python -m pip install -r requirements-inference.txt
python scripts/evaluate_benchmark.py --data-root /path/to/OpenRR-5k/data --model all --output outputs/official
```

CUDA BF16 inference is the default on CUDA. Install a CUDA-compatible PyTorch build for the local GPU; the controlled archived pass used PyTorch 2.11.0+cu130 on an A100. `--model past`, `--model jome`, or `--model arise` selects a single system. The default split is the 300 official validation pairs. `--split selection`, `--split locked` (internal holdout), or `--split all` selects the manifest-defined 300, 200, or all 800 pairs. The command accepts either the dataset's `data/` directory or its parent `OpenRR-5k/` without rearranging files. `--ids val_0001 val_0002` or `--limit 2` supports a short pilot.

The command writes per-image raw/JPEG100 RGB MSE, PSNR, local SSIM, split summaries, and execution/checkpoint metadata. Images retain native dimensions; metrics crop four pixels and average image scores equally. Default `--protocol historical` follows the retained complete-system evaluator: FP32 parameters, CUDA BF16 forward, channels-last layout, TF32 allowed, FP32 PSNR reductions, quality-100 JPEG with chroma subsampling disabled, and local 11×11 Gaussian SSIM. JPEG encoding rounds clipped unit-range RGB to 8-bit values. The released-output audit found a maximum absolute difference of 0.000228 between measured team-mean SSIM and published challenge values. Historical Table 6 JPEG PSNR values are 34.190890 (PAST), 34.347453 (JOME), and 34.225738 (ARISE); differences in hardware, PyTorch, CUDA, or Pillow can change remeasured scores. Historical LPIPS, DISTS, NIQE, and full-pipeline timings are retained statistics; this minimal command does not recompute them.

`--protocol controlled` uses contiguous native inference, disables TF32 matmul, and computes image MSE with float64 reductions, matching the primary raw protocol. It reports native network output and does not reconstruct matched aggregation operators. `--device cpu` or `--device mps` uses FP32 forward by default and is useful for checking operation, with different numerical behavior from CUDA BF16. Outputs identify the actual device, precision, protocol, and software versions. For the exact controlled CUDA protocol, uint8 RGB normalization occurs on the device before inference.

Verification covers a one-image A100 run of all three models, with a maximum absolute historical JPEG PSNR difference of 0.002065 dB from the recorded evaluation. The full benchmark has not been rerun with this direct evaluator, and exact historical score parity is not established. The final controlled loader implements the frozen evaluator's device-side normalization, but its GPU recheck was not executed because the Colab connection failed. Separately, a five-image PAST/JOME export using the frozen evaluator matched recorded raw PSNR within 2.14e-13 dB. [MODEL_MANIFEST.json](model/MODEL_MANIFEST.json) records these distinct verification scopes.

Add `--save-predictions` to retain native-resolution HWC float32 `.npy` predictions, rounded RGB8 `.png` copies, and the exact quality-100 `.jpg` bytes that were scored. PNG/JPEG are quantized representations; use `.npy` for raw pixel remeasurement. Output directories must be new to avoid overwriting an evaluation.

The frozen `scripts/evaluate_priority.py` remains unchanged for full matched-operator/Gram/geometry replay. Prepare a separate staging directory with `project/` copied from `model/project/`, `manifest.csv` copied from `data/manifest.csv`, `checkpoints/base.pt` and `checkpoints/jome.pt` copied from this repository, and the manifest-listed `data/...` images, then run:

```bash
python scripts/evaluate_priority.py --root /path/to/staging --output /path/to/new-results --device cuda --limit 0 --max-seconds 570
```

That retained pass used CUDA BF16 forward, FP32 matched operators, float64 reductions, and a four-pixel crop. New raw and historical JPEG scores remain separate. The compact records do not include raw residual tensors or spatial router maps; arbitrary spatial/residual-operator replay requires rerunning inference. The provided code supports evaluation; it does not reproduce model training. Historical M/N/Asymmetric/Dual ablations and SCTR comparisons are supplied as statistical evidence. External-system comparisons use released-output measurements and published aggregate context, with provider attribution in `data/capacity_context.csv` and `data/released_geometry.csv`.
